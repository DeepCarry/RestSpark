# 长休息独立分钟间隔 — V3交付

2026-11-10（Asia/Singapore），开发分支 `feature/settings-design-system-v1`。

## 最终行为

长休息直接设置分钟，六个预设为 **30、45、60、90、120、180分钟**。新用户默认60分钟，自定义整数30–180分钟。取消「工作周期」及换算文案，不再要求长休息间隔是短休息间隔的整数倍。

短休息与长休息分别累计工作时间。例如短40分钟、长60分钟：工作40分钟短休息，休息期间不累计，随后再工作20分钟进入长休息。两者同时到期时只进入长休息；长休息结束后重新安排短休息，避免连续补发。只启用一种休息也使用其自身的间隔。

提前提醒、推迟、手动休息、手动完成、严格模式和现有暂停入口继续保留。间隔设置变化会按已累计工作时间重算等待阶段，不能打断正在加载或进行中的休息。暂停/空闲/勿扰恢复沿用原入口的重置行为；没有改动人物、Logo、提醒窗口布局。

## 旧配置迁移

新增毫秒键 `longBreakInterval`。迁移在electron-store填充默认值前读取原文件：没有新键的旧配置按 `microbreakInterval × (breakInterval +1)` 转成分钟，保留旧的实际配置间隔；已有新键则直接保留。原值存入 `independentScheduleBackup`，用 `independentScheduleVersion` 保证幂等。

旧 `breakInterval` 保留用于历史/回退，不再驱动当前计时。旧的非标准或超出新范围的间隔继续保留并标注历史设置，只在主动编辑该字段时要求符合新范围。其他手工字段、短休息参数和外观等配置不被重写。

用户实际实例：原短间隔40分钟、旧2个周期＝80分钟，迁移后直接显示80分钟。已核对原文件全部既有字段逐项相等，仅新增上述3个迁移字段；没有将个人设置覆盖为新用户60分钟默认值。见 [实际实例检查](evidence/live-user-restart.json)。

## 审查与修复

独立只读审查发现并复现三项问题，均加入修复前失败、修复后通过的持久回归：

1. P1：窗口加载阶段保存间隔可调度另一类休息。新增显式starting状态，在发出开始事件时停止工作计时，禁止加载/进行中重排；主进程也防止两种窗口交叉创建。
2. P2：通知提前量被剩余时间缩短后，托盘和文案仍显示原提前量。保存实际提前量并用于等待、进度和通知文本。
3. P2：关闭睡眠暂停时，唤醒只校正旧timer可能先短后长补发。恢复等待阶段重新选择到期事件，长休息优先。

另补充加载中关闭/手动替换的回归，避免误认为休息未完成而立即重复。

真实用户切换实例时，旧进程关闭全部页面后仍持有单实例锁。已记录失败日志，在确认无页面且有配置备份后定点结束该退出未完成的旧进程，再正常启动新版并验证迁移；未把旧进程打开的新页面当作新后台验证。
